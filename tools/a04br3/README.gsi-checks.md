# Generic GSI preparation and offline compatibility evidence

These checks do not demonstrate boot completion, HAL service operation,
rendering, input, audio, or live AVB behavior.

The saved official Android 10 arm64 GSI is a user build, SDK29. Its image
SHA256 is 18a42a793798294183089e582c56bdf666e9d493523fb4389c6a3f7101ec6b60
and its length is 1498497024 bytes. The image was not modified. Read-only
e2fsck completed without reporting filesystem errors.

The current device vendor policy is generated by the public device tree
and vendor repositories. It declares platform policy version 29.0. Using
AOSP r47 host secilc, compilation of the following inputs succeeded:

- Official GSI /system/etc/selinux/plat_sepolicy.cil
- Official GSI /system/etc/selinux/mapping/29.0.cil
- Built vendor /etc/selinux/plat_pub_versioned.cil
- Built vendor /etc/selinux/vendor_sepolicy.cil

The flags match Android 10 init: -m -M true -G -N -c 30. Output is a
host-only policy file, never flashed. Successful compilation excludes a
missing-symbol policy-compilation failure for this exact input set, not
all SELinux runtime failures.

For VINTF, use AOSP host assemble_vintf. Merge the built vendor manifest
and all two installed vendor manifest fragments; add the known #18 kernel
version 4.14.141 and its complete generated .config through --kernel.
The official level-4 framework matrix must also include the device-specific
framework matrix metadata: the latter declares accepted SELinux versions
and AVB version. For this image it has only sepolicy and avb elements.
Copying those elements into a host-only level-4 matrix is sufficient to
represent these actual inputs. Do not compare the bare level-4 matrix and
mistake missing metadata for a vendor incompatibility.

PRODUCT_ENFORCE_VINTF_MANIFEST=true assemble_vintf -i <combined framework matrix>
-c <combined vendor manifest with kernel> -o <host-only output> returned 0.
This checks declared HAL requirements, declared policy version and the
supplied kernel configs. It does not verify actual kernel/services/AVB
on the device. Only the saved #18 config was supplied; the experimental
4.4 kernel is a different configuration and is not covered by that result.

A separate build recipe, build-generic-gsi.sh, builds the unmodified
android-10.0.0_r47 standard aosp_arm64-userdebug target. It binds only the
workspace path, uses a dedicated OUT_DIR, and does not inject the board's
device/vendor product into the generic system. The userdebug variant is
explicitly distinct from the saved official user GSI. Neither variant has
yet been demonstrated on the current hardware in this overnight trial.

Before writing another system image, restore device control, preserve the
current system and boot, and validate unattended rollback. A user image
has no normal adb-root/ro.debuggable console escape. Do not assume that
receiving kernel UART messages provides a usable shell.

## Graphics ELF inventory

check-gsi-elf-deps.py inventories explicit vendor roots with GNU readelf and
read-only debugfs listings of the official GSI. Six roots were checked:
32/64-bit GLESv2, hwcomposer.mt8167, gralloc.mt8167, and the composer 2.1
and allocator 2.0 service executables. Their vendor-side graph contained
49 ELF files, with no unlocated DT_NEEDED name in the chosen vendor and
GSI system/VNDK29/VNDK-SP29/runtime library directories.

REA open_binary separately bound the 64-bit GLESv2 root as ARM64 ELF,
SHA d793f3896fb02490adf7b83481e032e0f0cd86158f7e7ded9cc938cc61e6ddb4.
No native decompilation or execution was requested, and that session was
closed. The dependency inventory is ordinary GNU readelf evidence, not
REA runtime evidence. REA's lightweight binary-layout tool currently
advertises only an x86-64 profile, so that profile was not applied to ARM.

This is a bounded file-name inventory. It does not establish Android
namespace permission, symbol/version compatibility, relocation success,
dlopen targets, system-side dependency closure, or kernel ABI compatibility.
A zero unlocated-name count is not a successful GSI or graphics test.
